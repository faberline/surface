# Navigation bar design sources and scope

Google recommends the Flexible navigation bar over the taller Baseline bar. The initial Surface slice uses the compact vertical configuration. It adds a separate Material builder and keeps the original baseline, vector, badge and focus APIs. The compact viewport uses equally wide destinations. The rail and medium horizontal plans remain separate. [Google overview](https://m3.material.io/components/navigation-bar/overview) · [Google specifications](https://m3.material.io/components/navigation-bar/specs) · [Current Android Developers guidance](https://developer.android.com/develop/ui/compose/components/navigation-bar)

The Google token set resolves to a square 64 dp-high `SurfaceContainer`, a 56 × 32 dp fully rounded selected indicator, a fixed 24 dp icon, 6 dp outer padding, and a 4 dp gap above the label. The label uses the 12/16 Label Medium role. `SecondaryContainer` fills the selected indicator. `OnSecondaryContainer` colors its icon, and `Secondary` colors its vertical caption. Inactive icons and captions use `OnSurfaceVariant`. The state layers use 8% hover, 10% focus and 10% press. The bar grows when labels wrap at 200% text. Surface applies the explicit Level 2 elevation token. The current Compose short-bar implementation has a `Surface` without an explicit shadow. [Google token table](https://m3.material.io/_dsm/data/dsdb-m3/2026-11-19_06-20-01/TOKEN_TABLE.52865380210a9b69.json) · [Google measurements](https://firebasestorage.googleapis.com/v0/b/design-spec/o/projects%2Fm3%2Fimages%2Fma3ovtkk-5.png?alt=media) · [Pinned AndroidX implementation](https://android.googlesource.com/platform/frameworks/support/+/de12189a63496bd8aed010be245ce96a94f5873a/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/ShortNavigationBar.kt)

Google's keyboard table describes Tab moving between destinations. The accompanying figure shows Tab entering and an arrow moving focus. This slice follows the explicit table and uses Enter or Space to select. It retains authored focus order in RTL. The selected label requests Label Medium Emphasized. The stock Surface font can render that request with its regular face. The selected indicator and color still visibly identify the current page. [Google accessibility notes](https://m3.material.io/components/navigation-bar/accessibility) · [Keyboard figure](https://firebasestorage.googleapis.com/v0/b/design-spec/o/projects%2Fgoogle-material-3%2Fimages%2Fm0fr7kb3-03.png?alt=media)

The medium horizontal drawing marks 20 dp at the label end of the pill, while the resolved horizontal tokens and AndroidX implementation use 16 dp. Google recommends three to five destinations, while the AndroidX centered layout can handle six. These differences belong to the medium layout design. The compact builder accepts three to five cells under 600 dp and leaves each a full 56 dp or more. Expanded-width handoff, badge parity for this variant, animation, and live screen-reader speech remain separate evidence. [Google guidelines](https://m3.material.io/components/navigation-bar/guidelines) · [Android window classes](https://developer.android.com/develop/adaptive-apps/guides/use-window-size-classes)
